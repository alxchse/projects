For formulating the constraints, I originally did not realize that we needed to make and apply a list of individualized constraints before

    for r in range(n):  
        for c in range(n):
            # for each cell, check all 8 surrounding cells (including diagonals)
            for dr in [-1, 0, 1]: 
                for dc in [-1, 0, 1]:
                    # skip the cell itself (dr=0, dc=0) since we only want to check adjacent cells

                    # calculate the coordinates of the adjacent cell

So I asked Claude: 

    why can i not use the three general constraints i have formulated to encode

To which it responded: 

    Good question. Each constraint is applied in different loops:

    Row loop
    pythonfor r in range(n):
        add_exactly_k([var(r, c, n) for c in range(n)])
    For each row, you gather all cells in that row and say exactly k must be stars. You need one constraint per row, so you loop over rows and fix r while varying c.

    Column loop
    pythonfor c in range(n):
        add_exactly_k([var(r, c, n) for r in range(n)])
    Same idea but now you fix c and vary r. You can't combine this with the row loop because a row constraint and a column constraint are about completely different groups of cells — row 0 is [(0,0), (0,1), ...] while column 0 is [(0,0), (1,0), ...]. They just happen to share the same loop structure.

    Region loop
    pythonfor region in regions:
        lits = [var((r-1)//2, (c-1)//2, n) for r, c in region]
        add_exactly_k(lits)
    Same idea again — one constraint per region. But regions are irregular shapes found by BFS, not neat rows or columns, so the cells in each group are just whatever BFS collected.

So that certainly helped me get the encoding function together. It also told me that I need to check my < vs. <= 
and suggested I add the following line to avoid adding duplicate constraints:
    
    if (r, c) < (r2, c2):
        cnf.append([-convert2SAT(r, c, n), -convert2SAT(r2, c2, n)])
